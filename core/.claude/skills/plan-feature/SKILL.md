# 規劃新功能

需求：$ARGUMENTS

依序執行，**這個階段不要寫任何實作程式碼**：

1. **釐清需求**：列出需求中不明確的地方，一次問完（最多 5 題）。等使用者回答後再繼續。
2. **探索現況**：讀取相關程式碼。範圍大時交給 researcher subagent，只取回結論：
   - 會受影響的檔案與模組
   - 可重用的既有元件
   - 需要遵守的既有模式
3. **撰寫規格**：依 `docs/specs/_template.md` 建立 `docs/specs/<YYYY-MM-DD>-<slug>.md`，填寫：
   - 目標與非目標
   - 驗收條件
   - 設計（API、資料模型、流程）
   - 風險
4. **實作計畫**：在規格最後列出步驟，每步都要：
   - 夠小，一次可以完成並測試
   - 寫明要改哪些檔案
   - 寫明怎麼驗證
5. **等待確認**：向使用者摘要規格重點（5 行內），等使用者確認或修改後才開始實作。

若出現重大架構選擇（換套件、改資料模型、新增服務），另外在 `docs/decisions/` 依範本新增一份 ADR。
