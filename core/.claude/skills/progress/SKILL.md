# 更新進度紀錄

更新 `docs/progress.md`，整份檔案控制在 **40 行內**。它只回答三件事：現在做到哪、下一步是什麼、有什麼還沒解決。

1. **進行中**：目前任務、對應規格檔、各階段勾選、下一步（具體到檔案、函式或要使用者做的事）。只寫現況，不寫過程：不記時間戳流水帳，不重述每支指令的實作細節。
2. **仍有效的決策**：程式碼和其他文件都看不出來、而且還會影響後續工作的決策，一行一則，附日期。
3. **已知問題 / 待辦**：發現但還沒處理的問題。
4. **不要重複別處已有的內容**：
   - 已寫進其他 `docs/` 文件的結論，這裡只留連結或節號。
   - 長期適用的規則建議使用者寫進 `CLAUDE.md`，寫進去之後就從這裡刪掉。
5. **清理**（超過 40 行時一定要做）：
   - 已完成的任務、已結案的問題、已被取代的決策，以及想保留的過程細節，追加到 `docs/progress-archive.md` 最後，標上存檔日期；`progress.md` 的「已完成」每個里程碑只留一行。
   - 已過時、沒有追溯價值的內容直接刪除。
   - 不要為了更新而讀 `progress-archive.md`，只追加。

完成後用 3 行內回報更新了什麼。
